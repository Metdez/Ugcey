# 07-01: Stuck recovery + continuous memory

## Tasks
1. `ugecy/middleware/stuck.py`: `detect(messages) -> Stuck | None` (pure function) and `StuckMiddleware` (`awrap_model_call` appends the nudge to the system message; `has_search` decides between search and delegation wording). Record each detection with `experience.note_stuck(...)`.
2. `ugecy/memory/experience.py`:
   - `episode_from(messages, agent)`: task, final answer, tool counts, errors.
   - `record(store, ws, agent, episode, model)`: append the episode, merge lessons with the fast model, per-file locks, background tasks, `drain()` for tests.
3. `ugecy/middleware/memory.py`:
   - `LiveMemoryMiddleware(MemoryMiddleware)`: always reloads.
   - `ExperienceMiddleware(agent, model)`: `aafter_agent` builds the episode and schedules `record`.
4. `graph.py`: each subagent gets `LiveMemoryMiddleware([AGENTS.md, agents/<name>.md])`, `ExperienceMiddleware`, and `StuckMiddleware`. The orchestrator gets the same with `agents/orchestrator.md` and drops `memory=`.
5. Prompts: a shared memory and stuck footer appended to every subagent prompt (in `graph.py`).
6. Tests: detector cases, nudge injection, episode parsing, record/merge with a fake model, model failure fallback, the graph wiring.
7. Deploy (image v17), restart until the digest matches, then verify live: memory files appear in `/api/memories` after a run.

## Done when
- The full pytest suite passes.
- After a live run, `/memories/agents/<agent>.md` and `/memories/episodes/<agent>.md` exist with real content.
- A repeated failing action gets the stuck nudge, and the next model call is a `web_search`.
