<tasks>
1. **`worker/egress/bindings.ts`:** `export async function handleBindings(req: Request, url: URL, env: Env, props: RuntimeProps): Promise<Response>`. It implements every `bindings.internal` path:
   - `/d1/query`: `prepare(sql).bind(...params).all()` → `{results, meta: {changes, last_row_id}}`. Allow only single statements. Reject `ATTACH`, `PRAGMA` writes and `DROP` (the container is trusted code, but keep a guard).
   - `/d1/batch`
   - `/browser/markdown`: returns `{url, title, markdown}`, truncated to 60k characters. Validate the URL scheme is http(s), deny private IPs and hostnames, and use a 20 s timeout.
   - `/vectors/upsert` and `/vectors/query`: embed via `env.AI.run("@cf/qwen/qwen3-embedding-0.6b", …)`. Upsert with `{id, values, namespace, metadata: {...metadata, text: text.slice(0, 1000)}}`. Query with `returnMetadata: "all"`.
   - `/media/ingest`: `env.JOBS.send({kind: "media.ingest", asset_id, url, media_kind: kind})`. Return `{asset_id, queued: true, playback_url: url, thumbnail_url: null}`.
   - `/publish/schedule`: `env.PUBLISH_WF.create({id: post_id, params: {post_id, publish_at}})`. Return `{workflow_id}`. An existing instance id returns the same id.
   - `/metrics`: `env.METRICS.writeDataPoint`.
   - Errors use the `{"error": {code, message}}` envelope. Bodies are validated with small hand-written guards; no zod dependency is needed.
2. **`worker/workflows/publish.ts`:** `export class PublishWorkflow extends WorkflowEntrypoint<Env, PublishParams>`:
   - If `publish_at` is set, call `step.sleepUntil("scheduled slot", new Date(publish_at))`.
   - `step.do("publish", {retries: {limit: 5, delay: "1 minute", backoff: "exponential"}, timeout: "5 minutes"}, ...)` calls `env.AGENT_RUNTIME.getByName(env.WORKSPACE_ID).fetch("http://container/jobs/publish", {method: "POST", headers: {"content-type": "application/json", "Idempotency-Key": post_id}, body: JSON.stringify({post_id})})`. Throw on non-2xx so the step retries.
   - Finally `step.do("audit", ...)`: insert an audit row into D1 directly (`actor` system, action `publish.workflow`, status ok).
3. **`worker/queues/consumer.ts`:** `export async function handleQueue(batch: MessageBatch<JobMessage>, env: Env): Promise<void>`.
   - `media.ingest` for video: try Stream ingest (per the docs findings). On success, update D1 `assets` set `thumbnail_url` / `url` to the Stream playback URL. On failure, retry up to `max_retries`, then the message goes to the DLQ.
   - Images: keep the URL. Record a shortcut note: R2 copy once R2 is enabled.
   - `metric`: `writeDataPoint`.
   - Ack per message; retry on error.
4. **`scripts/bootstrap.sh`:** an idempotent `bash -euo pipefail` script using `pnpm exec wrangler`. It creates, if missing:
   - D1 `ugecy-db`
   - KV namespace `ugecy-cache`
   - queues `ugecy-jobs` and `ugecy-jobs-dlq`
   - Vectorize `ugecy-memory`, dimensions 1024, metric cosine. Verify the qwen3-embedding-0.6b output dimension in the docs and use it.
   
   It parses the IDs from `wrangler ... list --json` output where supported, and prints `D1_ID=...` and `KV_ID=...`. It must never touch the existing `resspark*` resources. Then it applies migrations: `wrangler d1 migrations apply ugecy-db --remote`. **Do not run it.** Write it, and check it with `bash -n` and `shellcheck` if available.
5. **`scripts/deploy.sh`** (do not run it). It performs these steps in order:
   - build the web app
   - substitute the IDs into a generated `wrangler.deploy.jsonc` from env `D1_ID` and `KV_ID`, via `node -e` JSON edit with comments stripped, or `sed` on the placeholders
   - `wrangler deploy --config wrangler.deploy.jsonc`
   - print the URL
6. **Tests:** vitest unit tests (`worker/test/bindings*.test.ts`) for URL validation, SQL guard, and body guards, using fake env objects.
