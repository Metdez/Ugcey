<tasks>
1. **ChatView.**
   - A scrollable column (max-w 48rem) with auto-scroll to bottom while streaming and a "Jump to latest" button.
   - Renders `UserMessage` and `AssistantMessage`, with `EmptyThread` when there are no messages.
   - The Composer is docked at the bottom.
   - The run status pill reads the `status` and `progress` slices: Working, "Paused · n approvals waiting", Error.
2. **AssistantMessage.** Renders `parts` in order:
   - `ReasoningBlock`: collapsed, "Thinking…" while streaming.
   - `ToolCallLine`: shows state text via `lib/tool-labels.ts` (create it in your dir, e.g. `chat/tool-labels.ts`), for example "Searching the web for …", "Fetched …", "Wrote /research/x.md". Args and output sit in a collapsible. A file-path arg links to `useUi().openInspector('files', {kind:'file', id})`.
   - `SubagentLine`: agent color dot, a "Research analyst is working…" / "Ran research analyst" label, and an expandable nested trace of `subagents[id].toolCallIds`, plus streamed text and the clamped result. "Open in Agents" calls `openInspector('agents', {kind:'subagent', id})`.
   - `InlinePlanCard`: todos progress "Plan · 3/7 done".
   - `ApprovalCard variant="inline"`.
   - Markdown text.
   - `AssetPreviewGrid`.
   - `TurnError` with Retry. Retry calls `threadActions.send` with the last user text.
   - A footer with a copy action.
3. **ApprovalCard.**
   - Reads `approvals[approvalId]` and renders each `ApprovalRequest` with a category icon by tool name:
     - generate_media → Clapperboard
     - publish_post → Send
     - device_* → Smartphone
     - else ShieldCheck
   - Title, agent, a key/value args preview and the estimated cost if present.
   - Buttons appear only for `allowed_decisions`: Reject (with reason chips: Off-brand · Unsupported claim · Missing #ad disclosure · Wrong account · Bad timing, plus free text), Edit (form generated from args: string→Textarea, number→Input, bool→Switch, object→JSON Textarea with validation), and Approve (⌘↵ when focused).
   - On submit, call `threadActions.decide(interruptId, decisions)`, with one `Decision` per request in the same order: `{type:'approve'}` | `{type:'edit', args}` | `{type:'reject', message}`.
   - Once the status isn't `pending`, render a resolved line.
   - `variant="panel"` is the same card in a denser layout.
4. **Assets.**
   - `AssetThumb`: aspect 9/16, status skeleton with "Generating with Higgsfield…", a failed state, and a `SIMULATED` badge when `mode==='mock'`. Video uses a `<video muted playsInline>` hover preview.
   - `AssetPreviewGrid`: renders 1, 2–4, or "+N".
   - `AssetLightbox`: a Dialog bound to `useUi().lightboxAssetId`, showing the player or image, prompt, model, provider, mode and a download link.
5. **Composer.**
   - Textarea with autosize 1–8 rows. Enter sends; Shift+Enter adds a newline (respect `isComposing`).
   - The Send button becomes Stop while streaming (Esc stops).
   - Disabled when `locked` or `offline`.
   - Slash menu with `/research /patterns /script /generate /publish /analyze`. Each inserts a prompt template.
6. **EmptyThread.**
   - H1 "What are we making today?".
   - A 2×3 starter grid. Use `/api/config` `starter_prompts` when available via a prop or a fetch in your component, falling back to the six starters in UI-SPEC §6. Clicking one sends it.
7. **Tests** (vitest is set up by WP-A; if it isn't there yet, write the tests anyway; the orchestrator runs them after merge):
   - ApprovalCard decision payloads
   - tool-labels
</tasks>
