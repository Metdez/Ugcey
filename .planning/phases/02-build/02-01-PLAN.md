<tasks>
1. **Tokens, fonts and Tailwind.**
   - Put the UI-SPEC §7 CSS variables into `src/index.css`. Include the `success`, `warning`, `info` and `agent-*` tokens and map them in `@theme inline`.
   - Keep `tw-animate-css`. `<html class="dark">` is the default.
   - Add `@fontsource-variable/inter` and `@fontsource-variable/jetbrains-mono`.
   - Keep Radix-based shadcn (locked decision L4: do NOT switch to Base UI; use `asChild` and Sonner).
   - If the shadcn registry still offers them, add these components: `alert-dialog`, `breadcrumb`, `aspect-ratio`, `checkbox`, `spinner`, `empty`, `item`, `field`, `input-group`, `button-group`. If any is missing, write a tiny equivalent under `src/components/common/`.
2. **Stores and data.**
   - Implement `thread-store.ts` `threadActions` with `streams.*` from `lib/api.ts`, plus a pure reducer `src/stores/apply-event.ts`: `applyEvent(s: ThreadSnapshot, e: UiEvent): ThreadSnapshot`. It maps every `UiEvent` type:
     - `message.delta` and `reasoning.delta` append text/reasoning parts to the current assistant `UiMessage`, keyed by `message_id`. Text from a subagent (`agent !== "orchestrator"`) goes into `subagents[parent_call_id].text`, not into the main message.
     - `tool.started`, and `tool.completed` with `name === "task"`, become a subagent part. Other tools become `ToolCallView`s and tool parts. When `parent_call_id` is set, the tool call id goes into that subagent's `toolCallIds` and **not** into message parts.
     - `subagent.started` and `subagent.completed` update `subagents`.
     - `todos.updated`, `files.updated`, `source.added` (dedupe by url) and `asset.updated` (also add an assets part) update their collections.
     - `approval.requested` adds `approvals[interrupt_id]` (status pending), adds an approval part, and sets status `interrupted`.
     - `progress` sets the progress line. `run.completed` sets status idle, error or interrupted. `error` sets `error` and adds an error part.
     - Track `lastSeq` and ignore events with `seq <= lastSeq` for the same `run_id`.
   - `openThread(id)` loads `api.getThread(id)` and converts `ChatMessage[]` history to `UiMessage[]`: assistant tool calls become tool parts, and tool messages become outputs. It sets todos, files, sources and `pending_approval`, and loads `api.listAssets(id)`. If the thread is running, it calls `streams.attach(id, 0)`.
   - `send(text)`: create the thread via `api.createThread` if `threadId` is null (title = the first 60 chars of the text), push the user message, then `streams.run`.
   - `decide(id, decisions)`: mark the approval approved, edited or rejected, then `streams.resume`.
   - `stop()`: call `api.cancel` and abort the fetch.
   - On `ApiError` 401, set status `locked`. On a network failure, set `offline`.
   - Write `src/stores/workspace-store.ts` (yours): config, threads list, accounts, health. Refresh threads after each run.
3. **Mock adapter.**
   - `src/fixtures/mock-run.ts` is a realistic `UiEvent[]` timeline: orchestrator reasoning, then `write_todos` (todos), then a `task` call to research-analyst (subagent events with nested `web_search` and `fetch_page` tools, `source.added`, one failing tool), then files, then creative-strategist, then a `generate_media` approval.
   - With `?mock=1` or `VITE_MOCK=1`, `send()` replays it with delays. After approval, a second timeline produces `asset.updated` (queued, then completed, using placeholder SVG data URIs) and a final message.
   - This lets B and C develop visually.
4. **Shell components** (UI-SPEC §3 WP-A table), under `src/components/shell/` and `common/`:
   - AppShell (SidebarProvider + ResizablePanelGroup with main and inspector, plus the InspectorRail)
   - LeftSidebar, NewChatButton, ThreadNav (grouped by date, status dots), AccountsStatus (from `api.listAccounts`), MainHeader (title, ModelChip from config, RunStatusBadge, MOCK badge when any mode is mock), SystemBanners (mock, offline, locked with an unlock form that navigates to `/api/edge/unlock?key=<input>`)
   - InspectorPanel, which renders `<InspectorTabContent tab>` from `@/components/inspector`, InspectorRail (labels from `TAB_META`, badge counts from stores), and InspectorSheet below 1024px
   - CommandPalette and ShortcutsDialog
   - `common/{agent-avatar, status-dot, relative-time, empty-state}`
   - `AgentAvatar` maps agent names to `--agent-*` colors: research-analyst=research, creative-strategist=creative, compliance-critic=creative, production-coordinator=production, publishing-coordinator=publishing, device-operator=device, analytics-analyst=analytics, orchestrator=orchestrator.
5. **Wiring.**
   - Mount `<ChatView/>` in the main panel and `<AssetLightbox/>` once.
   - `hooks/use-shortcuts.ts`: ⌘K, ⌘I, ⌘/, ⌘⇧O, `/`, and G-chords.
   - Routes use the URL hash or `?t=<threadId>`. Use a tiny location sync: no react-router dependency unless needed; if you add it, use one route.
   - Fetch `/api/config` on boot. Sonner `<Toaster theme="dark"/>`.
6. **Tests.** Add vitest + @testing-library/react (`pnpm --filter web add -D vitest @testing-library/react jsdom`) and a `"test": "vitest run"` script. Write unit tests for `applyEvent` (subagent nesting, approval, dedupe/seq) and `readSse` (chunk boundaries, comments).
</tasks>
