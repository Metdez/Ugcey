# 08-01: Dropbox media library

The design is in 08-CONTEXT.md. Rules that still apply: no mock data, no run limits, approvals only for posting and payments, and secrets are never printed.

## Operator steps (Dropbox console, once, about 2 minutes)
1. In https://www.dropbox.com/developers/apps, open the app.
2. **Permissions:** tick `account_info.read`, `files.metadata.read`, `files.metadata.write`, `files.content.read` and `files.content.write`, then Submit.
3. **Settings → OAuth 2 → Redirect URIs:** add `https://ugecy.zh-a16.workers.dev/api/dropbox/callback`.
4. After deploy: click **Connect Dropbox** in the app sidebar and approve.
5. On the iPhone: sign in to the Dropbox app (the operator's own step).

## Wave 1: Worker (TypeScript)
- `worker/dropbox/` is a mirror of `worker/glasshand/`:
  - `oauth.ts`: authorize URL, `exchangeCode`, `refresh`, `revoke`. It uses injectable fetch and Basic auth with the app key and secret.
  - `store.ts`: a `dropbox(k,v)` table in DO SQLite.
  - `core.ts`: `startAuthorize` (random state, 10 min TTL), `finish(code,state)`, `token(stale?)` (lock, 60 s skew, clears tokens when a refresh is rejected), and `status` (`get_current_account`, cached 5 min).
  - `egress.ts`: `/_ugecy/status` is answered locally. Allowlisted POSTs go to `https://api.dropboxapi.com`. Only `content-type` and `accept` are forwarded, plus the bearer. One retry after a 401.
  - `routes.ts`: `GET /authorize` (302), `GET /callback` (verifies state, then 302 to `/?dropbox=connected|error`), `GET /status`, `POST /disconnect`.
- `worker/do/agent-runtime.ts`: `dropbox.internal` in `VHOSTS`, the Dropbox RPCs, and `UGECY_HAS_DROPBOX: "true"`.
- `worker/egress/gateway.ts`: a `case "dropbox.internal"`.
- `worker/index.ts`: `app.route("/api/dropbox", dropbox)` after `requireKey`.
- `worker/env.ts`: `DROPBOX_APP_KEY?` and `DROPBOX_APP_SECRET?`.
- Tests in `worker/test/dropbox.test.ts`:
  - state mismatch is rejected;
  - a code exchange stores the tokens;
  - a refresh at expiry, and a rejected refresh that clears the tokens;
  - the allowlist;
  - a 401 retry;
  - `not_configured` when the secrets are missing.

## Wave 2: Python (parallel with wave 1; the contract is the INTERNAL-API.md section)
- `ugecy/integrations/storage/dropbox.py`, `DropboxClient`:
  - Edge mode uses `http://dropbox.internal`. Local mode uses `api.dropboxapi.com` with a token refreshed from `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET` and `DROPBOX_REFRESH_TOKEN`.
  - Methods: `status`, `save_url`, `check_job`, `get_metadata`, `list_folder(+continue)`, `temp_link`.
  - Retries a 429 after `Retry-After`.
  - `ugecy/integrations/storage/auto.py` provides the live status with a 15 s cache, and an Off provider that raises `NotConnected(STORAGE_OFF)`.
- `ugecy/storage/backup.py`:
  - `dropbox_path(asset)` handles the slug, date, folder by kind and extension.
  - `backup_asset(asset)` runs save_url, polls the job (3 s interval, up to the 15-minute transfer window), handles conflicts by checking metadata, then calls `set_asset_dropbox` and emits `asset.updated`.
  - `reconcile()` covers every completed asset that is unsaved and under 7 days old, with a concurrency of 3 for Dropbox rate limits. Background tasks are tracked like the experience recorder.
- Contracts:
  - `Asset.dropbox_path` and `dropbox_status` in `contracts.py` and `packages/contracts/src/models.ts`.
  - `ProviderModes.storage`.
  - `migrations/0002_asset_dropbox.sql`, which adds two columns, plus the matching change to `persistence/schema.sql`.
  - `AppStore.set_asset_dropbox`; the upsert excludes the `dropbox_*` columns from its update set.
- Hooks:
  - `tools/media.py:_poll` schedules a backup after `_save(completed)`.
  - `main.py` startup runs reconcile after `resume_media_jobs`.
  - `api/misc.py` gains `POST /api/storage/backfill`, `/api/config` reports the live storage mode, and `/api/assets` swaps in a temporary link after 6.5 days.
- `ugecy/tools/dropbox.py` adds `dropbox_status`, `list_dropbox_media`, `browse_dropbox`, `save_to_dropbox` and `dropbox_backfill`. It is registered in `modules.py`, added to the production, publishing and device agents, and has no `interrupt`.
- Prompts and memory:
  - The device-operator step "get media onto the phone" becomes the Dropbox app flow, with Safari as a fallback.
  - The production prompt notes that outputs are auto-saved to Dropbox.
  - The seed template `skills/_memory/AGENTS.md` gets a Dropbox line.
  - At deploy, the same how-to is appended to the live `/memories/AGENTS.md` and `/memories/agents/device-operator.md` through `PUT /api/memories`.
- Tests:
  - naming and extensions;
  - the save_url paths for complete, async and failed jobs;
  - conflict means already saved;
  - reconcile skips saved and expired assets;
  - a later `_save` does not wipe the Dropbox fields;
  - tool outputs;
  - the off mode returns not-connected (no fake data);
  - the temporary-link swap.

## Wave 3: Web
- `components/shell/accounts-status.tsx`: a Dropbox row showing the status dot and account name, with Connect (`window.location = /api/dropbox/authorize`) and Disconnect.
- `lib/dropbox.ts`: a client for `status` and `disconnect`, and `api.backfill()`.
- On `?dropbox=connected`: show a toast, call `POST /api/storage/backfill`, then clean up the URL.
- `asset-thumb.tsx` and `asset-lightbox.tsx`: a Dropbox badge (saved, saving or failed) and the Dropbox path.
- `lib/not-connected.ts`: a storage message.

## Wave 4: Ship
1. Pipe `DROPBOX_APP_KEY` and `DROPBOX_APP_SECRET` from the environment into `wrangler secret put` (values never echoed).
2. Run `wrangler d1 migrations apply ugecy-db --remote` (adds two columns).
3. Build and push image v19, update the digest, deploy, then restart until the running image matches.
4. Docs: an INTERNAL-API.md `dropbox.internal` section, an architecture doc paragraph, and README secret lines.
5. Update the STATE and ROADMAP entries and commit.

## Verification
- pytest, the worker vitest suite and the web build all pass, and ruff is clean.
- `/api/dropbox/status` reports `connected:false` before Connect and returns the account after it. `/api/config` then shows `storage: live`.
- Backfill: `POST /api/storage/backfill` saves all 35 current assets. `browse_dropbox("/Ugecy")` lists 32 images and 3 videos, and every asset shows `dropbox_status=saved`.
- New media: a fresh `generate_media` is saved to Dropbox within about a minute of completing, and its badge appears in the Assets tab.
- Agent: a chat asking where the latest video is gets `list_dropbox_media` back with the path and phone steps. Once the operator has signed in on the phone, the device-operator finds the file in the Dropbox app and saves it to Photos.
